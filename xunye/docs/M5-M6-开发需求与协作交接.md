# 寻页 XunYe：M5 / M6 开发需求与协作交接文档

版本：1.0 · 日期：2026-11-27 · 面向：接手作者端和管理端开发的协作者

## 1. 交接目标与依据

在现有M1～M4基础上，完成内容生产和管理运营闭环：

作者入驻 → 创建作品 → 编写章节 → 提交审核 → 管理员通过/驳回 → App展示或作者修改重提。

- M5：App作者创作 + 管理端最小审核工作台，必须能完整演示上述流程。
- M6：补全Web管理端模块、角色权限和运营统计。
- 依据：原始《寻页设计文档》的M5/M6范围，以及当前代码和`docs/M4.md`中的最新规则。
- 本文是后续开发要求，不表示这些功能已经完成。本文明确的新规则优先于原设计中已过时的VIP折扣和MQ资金流水设计。
- 作者端/管理端的接口路径、草稿方式、角色权限矩阵是本交接建议采用的实现基线；开工时写入接口说明并据此联调，必要变更通过PR说明。

## 3. 必须保留的当前业务规则

### 3.1 阅读与VIP

| 作品类型 | 有效VIP | 非VIP/已过期VIP |
| --- | --- | --- |
| 会员专属作品 | 所有已上线章节可读 | 所有正文不可读，即使标记免费或存在旧购章记录；不可单章购买 |
| 普通作品免费章 | 可读 | 可读 |
| 普通作品付费章 | 畅读，不产生购章扣款/购买记录/作者分成 | 实际购买后可读 |

- 普通作品已经购买的章节，在VIP过期后仍可读；普通作品作者本人已有阅读豁免保留。
- 会员专属作品的公共阅读接口只认有效VIP，作者预览走独立创作接口并验证作品归属，不在公共接口增加旁路。
- 会员专属列表、作品简介、公开目录可以浏览，未审核正文不能泄露。
- 所有VIP套餐阅读权益相同，仅价格和天数不同；历史discount字段保留兼容，不恢复折扣购章。
- 续费从未到期的旧到期日顺延，余额、VIP状态和购买凭证不缓存为授权依据。

### 3.2 资金与MQ

- 金额使用Long整分；所有余额修改必须有流水，并在同一数据库事务提交。
- 继续使用现有账户行锁、条件更新、提交标识幂等策略；不能仅靠前端按钮禁用或Redis短锁保证资金正确。
- VIP订阅支出已有流水类型7；不得按原设计误记为购章类型2。
- MQ用于通知、订单超时等后续动作；扣余额、资金流水、购买记录和VIP开通不能改为异步最终入账。
- 新审核通知若使用MQ：审核与`mq_outbox`事件同事务保存，消费者幂等；不要在数据库提交前直接发成功消息。
- 阅读点击事件继续Redis聚合，不在M5/M6擅自接入MQ；点赞沿用当前实现，不能为了统计重做交易或互动链路。

## 4. M5需求：作者创作与审核闭环

### 4.1 作者入驻

基线采用原设计的轻量入驻：登录且账号正常的用户确认协议后，将`user.is_author`从0改为1，不另建复杂申请审批系统。

- 我的页面增加“作者中心”；非作者展示入驻入口，已入驻进入作品列表。
- 入驻可重复提交，重复操作返回当前作者状态；禁止通过该接口修改余额、VIP、封禁状态等字段。
- 每个创作写接口都在服务端检查登录、账号状态和作者身份，不能只隐藏前端按钮。
- 不增加实名、提现、签约和作者等级功能。

### 4.2 作品管理

作者可分页查看自己全部作品及审核状态，可新建、编辑、预览、提交审核。

输入字段：书名、分类、封面URL、简介、默认单章价格、连载/完本状态。长度依照现有数据库限制并加`@Valid`校验。

- 封面第一版允许填写URL并展示预览、缺图占位；文件上传/对象存储不是本阶段必需项。
- `authorId`由登录上下文赋值；作者名由服务端取用户信息生成快照。
- 作者不能设置审核通过、会员专属标记、运营下架状态、统计计数、作者归属。
- 分类必须存在且启用；默认单章价需为正整分。
- 已上线作品修改书名、简介、封面等公开内容，按下面的重新审核规则处理，不能绕过审核直接发布。
- 删除限制：本阶段不提供已上线作品和有交易关联作品的硬删除；作者可编辑未上线内容，管理端使用下架处理公开作品。

### 4.3 草稿、送审与重新编辑

现有`audit_status`只有0待审、1通过、2驳回，不能把未提交草稿也放进待审队列。

建议最小实现：新增独立`submit_status`字段（作品、章节均适用），0未提交、1已提交。沿用原audit_status数字，不能修改其已有含义。

| 场景 | submit_status | audit_status | 管理员待审列表 | 公共读取 |
| --- | --- | --- | --- | --- |
| 新建草稿/撤回待审 | 0 | 0 | 不出现 | 不可见 |
| 提交审核 | 1 | 0 | 出现 | 不可见 |
| 审核通过 | 1 | 1 | 不出现 | 符合作品上线条件时可见 |
| 审核驳回 | 1 | 2 | 不出现 | 不可见 |
| 修改驳回稿/已通过内容 | 0 | 0 | 不出现 | 本版本重新通过前不可见 |

兼容已有已通过数据时，迁移需将已有记录置为已提交，不可让旧作品突然失去可见性。公共读取仍必须检查审核通过、作品未下架和VIP/购章规则。

本阶段采用单版本重新审核：已通过章节修改后暂时不可公开阅读，重新通过后恢复；购买凭证保留。作者点击保存前应提示影响。保留旧公开版本、新稿独立审核属于后续增强，不在本阶段暗中混用两种方式。

需提供撤回待审操作，撤回与审核并发时采用状态条件更新或行锁，只能一个操作成功。驳回原因必填，作者详情展示最近驳回原因并可查看历史审核记录。

### 4.4 章节管理

- 只允许管理自己作品下的章节；分页目录、草稿保存、编辑、预览、送审、撤回、查看审核结果。
- 标题、正文非空且有明确长度上限；服务端计算字数，约定去空白后的字符数，不信任前端传字数。
- `sort`必须为正数，同一本书序号唯一；按现有`UNIQUE(book_id, sort)`处理冲突，返回可读错误。
- 同时两次创建相同序号时只能一条成功；前端提示刷新目录，不静默覆盖。
- 普通作品可设置免费/付费；免费章有效价格为0，付费章指定正价格或继承作品默认正价格。
- 会员专属作品创作页隐藏免费/付费售卖选项并提示“所有章节仅VIP可读”；保留兼容字段，服务端仍以作品专属标记决定阅读权限。
- 章节预览使用专用受保护接口，拥有者可以看自己的草稿和会员专属正文，不增加浏览统计或购买记录。
- 有购买凭证的章节不能硬删除；不实现移章到其他作品、批量覆盖或随意变更付费章节归属。

### 4.5 管理员最小审核工作台（M5交付内容）

M5需要一套可用的管理员登录、作品审核、章节审核页面，不能仅靠手工SQL完成审核。M6在此基础上扩展。

- 待审列表支持按作品、作者、提交时间筛选，显示作品/章节标题与正文预览。
- 管理员能通过/驳回；驳回必须填写原因。
- 作品未通过时允许作者存章节草稿，但章节不得上线；首次章节送审要求父作品审核通过且未运营下架。
- 审核动作与审核记录必须同事务，审核前检查状态仍是“已提交待审”。
- 两个管理员审核同一版本：一个成功，另一个得到状态变化提示，不得后写覆盖先写。
- 增加版本号或等价校验：管理员预览版本与提交审核版本必须一致，防止作者编辑后旧页面误审新内容。
- audit_record当前target_type为1章节/2帖子/3回复/4评论；作品审核建议新增5，并集中放constant或枚举，不能覆盖旧类型。
- 记录审核人、目标类型/ID、结果、原因、版本与时间。作者只能读取自己内容的审核记录。

### 4.6 字数与更新统计

- 作品总字数统计当前审核通过、未删除章节，不含草稿/驳回稿。
- 首次通过增加、编辑退回草稿减去旧公开字数、重新通过再计入；重复审核不重复累加。
- 建议事务内按已上线章节重算或使用可证明幂等的增量更新，避免直接无条件`word_count += n`。
- 创作编辑不冒充“公开章节更新”；公开更新排序应以章节通过审核为依据，必要时新增`last_publish_time`并适配现有更新榜。
- 如果触及现有缓存，提交后失效相应详情/目录缓存；不能缓存未授权的公共正文响应并跨用户复用。

### 4.7 作者收益

- 展示本人的购章分成、打赏收益、当前余额和明细；复用type4/5等现有资金数据。
- 只统计实际入账，不把读者总支付额、VIP畅读次数或所有VIP订阅费当作作者收入。
- 本阶段不做提现和VIP收入分配，不改变现有购章分成规则。

## 5. M6需求：管理端全模块

### 5.1 管理员认证与权限

- 管理端Vue3 + Element Plus，独立登录页、布局、导航、分页、加载态、空态、错误反馈；修改操作成功后刷新受影响数据。
- 后端`/api/admin/**`默认全部鉴权，仅明确排除登录等必要公开认证入口；浏览器OPTIONS预检正常放行。
- App token必须不能访问管理接口，admin token不能冒充App用户。现有JwtUtils已区分userId/adminId，但完整管理员拦截器、角色授权仍须实现。
- 后端校验签名、过期、adminId、管理员正常状态与数据库当前角色；角色不能只相信前端或旧token。密码BCrypt，不返回哈希。
- 退出登录使当前token失效，可复用黑名单机制但需区分身份域；封禁管理员立即阻断后续请求。

建议角色矩阵（服务端强制，前端据此显示菜单）：

| 能力 | 超管1 | 运营2 | 审核员3 |
| --- | --- | --- | --- |
| 审核作品/章节/帖子/回复、处理评论 | 是 | 是 | 是 |
| 上下架、分类、充值/VIP套餐配置 | 是 | 是 | 否 |
| 用户封禁/解封 | 是 | 是 | 否 |
| 订单流水、运营统计 | 是 | 是 | 否 |
| 人工余额调整、管理员管理 | 是 | 否 | 否 |

管理员管理为M6增强项；若暂不提供页面，也必须有安全的本地初始化脚本与角色测试账号生成方式。禁止提供可公开调用的管理员注册接口或把真实口令提交Git。

### 5.2 管理模块清单

| 模块 | 必须支持的功能 | 验收重点 |
| --- | --- | --- |
| 作品管理 | 条件查询、详情、审核、下架/恢复、设置会员专属 | 恢复不等于审核通过，作者无权自行撤销运营下架 |
| 章节管理 | 待审/已审查询、正文、通过/驳回、审核历史 | 重复操作与并发审核不重复计数 |
| 分类管理 | 新增、编辑、排序、停用 | 被作品引用的分类不能硬删；停用后禁止新选择，历史作品可展示原分类名 |
| 用户管理 | 搜索、详情、封禁/解封、作者/VIP状态查看 | 不泄露密码；封禁后写接口受限 |
| 评论管理 | 书评/章评查询、隐藏、恢复 | 隐藏后公开列表不可见；点赞/评论计数口径一致 |
| 论坛管理 | 帖子/回复审核、驳回原因、封帖/恢复、逻辑删除 | 保留本人可见状态提示；公开计数不泄露待审内容 |
| 交易记录 | 充值订单、购章、打赏、VIP订阅、余额流水查询 | 按用户/时间/状态筛选，禁止直接编辑已完成交易 |
| 充值档位 | 金额、赠送、排序、上下架 | 旧订单按快照结算，新配置不改历史金额 |
| VIP套餐 | 名称、价格、天数、排序、上下架 | 不恢复购章折扣；统一畅读权益；不重写历史订阅快照 |
| 审核/操作记录 | 查询审核历史及敏感管理动作 | 记录操作者、对象、前后变化、原因、时间 |
| 仪表盘 | 汇总卡片、近7/30日趋势 | 指标口径见下节，不把资金流入流出重复当收入 |

### 5.3 作品会员专属切换边界

- 普通作品改为会员专属前，检查是否存在有效历史单章购买记录；存在则拒绝切换并提示原因。本阶段不做退款或追溯剥夺购买权益。
- 无历史购买的作品可以由有权限管理员切换，需确认并记录操作日志；作者不能设置此字段。
- 专属改普通时必须检查章节售卖配置；可选免费章或有效正价付费章，配置不完整时拒绝，不发布0元但仍锁定的章节。
- 不批量覆盖历史价格/免费标记/购买记录；原公共VIP权限优先级不能改回“先免费再判断专属”。

### 5.4 人工余额调整

仅超管可用，输入用户、增加/减少、正整数分金额、必填原因、唯一requestId。

- 账户行锁、余额更新、余额流水、调整记录和管理员日志同事务；不足不能扣成负数，溢出需明确失败。
- 重试同标识且参数一致返回原结果；同标识修改对象/金额/方向应冲突，不能重复调账。
- 现有type6只能表达“管理员调整”，amount又为正数，不能仅靠备注猜方向：新增调整记录保存signed delta、adminId、requestId、reason，并在流水DTO明确方向；或设计等价且兼容的方向字段。
- 保留旧流水类型，更新App流水展示使新增/扣减方向正确。禁止直接复用充值类型冒充真实充值。
- 不提供直接修改余额的通用用户编辑接口，不允许编辑或删除历史流水。

### 5.5 运营统计口径

| 指标 | 明确定义 |
| --- | --- |
| 用户总数/新增用户 | 未逻辑删除用户；新增按create_time统计，封禁不视为删除 |
| 当前有效VIP数 | 正常且未删除用户中vip_expire_time晚于当前时间的人数 |
| VIP订阅笔数/金额 | 成功订阅记录笔数/实付金额；续费也计一次，不等同会员人数 |
| 已付充值额 | 仅已支付订单amount之和，不含赠送，排除待付/关闭订单 |
| 充值赠送额 | 已支付订单bonus_amount单独统计，不当现金收入 |
| 购章消费额 | 实际购买记录amount之和，VIP畅读不计购章交易 |
| 打赏额 | 打赏记录amount之和，不能把双方流水各加一次 |
| 章节发布数 | 首次审核通过的章节数；重新审核不能重复算首次发布 |
| 浏览量 | 当前是访问计数，不称独立读者数；Redis尚未刷库的数据存在延迟，页面说明口径 |

- 趋势按Asia/Shanghai自然日，近7/30日包含今天，不足日期补0，开始日期包含、结束日期用次日零点排除。
- 新增`first_published_at`或等价首次发布记录支持章节发布趋势；旧数据回填应标注估算来源，不把迁移当天当成所有历史章节发布日期。
- 充值趋势按实际支付时间，订阅/购章/打赏按交易成功记录时间，不使用计划过期时间统计收入。
- 不把“充值+购章+打赏+订阅”相加叫平台现金营收，充值与余额消费属于不同口径；页面分别展示，不做财务利润报表。

## 6. 建议接口边界与联调契约

以下为新增接口建议，正式实现时在`docs/M5-API.md`、`M6-API.md`给出字段、分页、成功/失败示例。若当前路由已存在，优先兼容，不重命名M1～M4接口。

| 前缀 | 示例能力 |
| --- | --- |
| `/api/app/author` | `POST /join`入驻，`GET /status`状态 |
| `/api/app/author/books` | GET本人列表、POST建稿、GET/PUT `/{id}`详情/编辑，POST `/{id}/submit`、`/{id}/withdraw` |
| `/api/app/author/books/{bookId}/chapters` | GET目录、POST章节草稿 |
| `/api/app/author/chapters/{id}` | GET/PUT详情/编辑，GET `/preview`正文预览，POST `/submit`、`/withdraw` |
| `/api/app/author/income` | GET汇总与分页明细 |
| `/api/admin/auth` | 登录、当前管理员信息、退出 |
| `/api/admin/books`、`/chapters` | 分页、详情、审核与运营状态修改 |
| `/api/admin/categories`、`/users` | 分类、用户管理；余额调整单独受权接口 |
| `/api/admin/comments`、`/forum/posts`、`/forum/replies` | 内容治理 |
| `/api/admin/recharge-plans`、`/vip-plans` | 档位与套餐配置 |
| `/api/admin/orders`、`/purchases`、`/tips`、`/subscriptions`、`/balance-flows` | 交易只读查询 |
| `/api/admin/dashboard`、`/audit-records`、`/operation-logs` | 统计及留痕查询 |

- 统一返回`{code,msg,data}`，复用Result、BizException和全局异常处理，不创建第二套响应体系。
- 当前JSON配置可能把数字序列化为字符串：前端按String比较code，ID保持字符串避免BIGINT精度损失；金额按整分处理，不用浮点直接累加大额。
- 分页使用`pageNum/pageSize`，响应包含records/current/size/total；最大页长统一约束。
- 作者身份、管理员身份来自各自登录上下文；所有详情/修改接口服务端做归属和角色检查，不能相信请求中的authorId/adminId。
- 更新/审核DTO携带version（或等价更新时间条件），冲突返回409；字段长度、状态、排序、价格等均服务端校验。
- 错误区分未登录401、无权限403、参数错误400、冲突409，正文业务码与HTTP处理沿用现有约定，不只返回“系统错误”。

## 7. 数据库迁移要求

先检查现有表结构和索引，再提供`m5-migration.sql`与`m6-migration.sql`；演示数据独立脚本，说明执行顺序和重复执行策略。

可能新增：作品/章节提交状态、版本号、首次发布时间、公开更新时间、作品审核类型、管理员操作日志、人工余额调整幂等记录。字段与迁移以最终方案为准，必须说明默认值、旧数据回填和索引。

- 禁止对已有开发库直接重跑含DROP TABLE的`xunye.sql`；该文件仅供确认无数据的新库初始化。
- 全新库初始化顺序与已有M4库升级顺序分别写清；不得默认M3/M4演示数据可反复执行。
- 保留已有主键、外键关联习惯、状态含义和历史交易；逻辑删除不影响购买记录追溯。
- 注意现有`UNIQUE(book_id,sort)`：逻辑删除章节后也可能占用序号，不能承诺删除后随意复用；本阶段避免删除已上线章。
- 审核状态变更、字数统计、审核日志同事务；有新增MQ事件时本地消息也在同事务中。
- 管理员初始账户通过本地脚本或环境参数创建，凭据不提交；交付安全的example配置，不提交私密配置。

## 8. 代码规范与注释要求

- 后端沿用Java21、Spring Boot3、MyBatis-Plus；Service必须拆接口和impl。
- Controller只做参数绑定、身份读取、调用Service和响应；实体不直接出接口。
- 状态码、审核目标类型、权限常量、分页上限放constant或枚举；运营价格和天数放数据库。
- Controller/ServiceImpl用中文注释说明注解作用、权限边界、状态转换、事务、幂等、锁与失败处理。
- 复杂lambda、条件更新、SQL说明等价业务含义；不要只有“查询数据”“更新数据”这类重复方法名的注释。
- M5无需新增审核MQ链路即可完成主流程；如新增通知，复用MessageTransport、BusinessEventService、OutboxPublisher，新增事件分流需显式支持，不能以当前“非订单都进VIP Topic”直接发送任意新类型。
- 不仅修页面可见性：用户越权、未审核正文、被封禁写入都需后端拦截。

## 9. 朋友电脑启动准备

1. 从GitHub克隆完整仓库，并确认已包含本次M4和本文；检查提交记录而不是复制`target`、`node_modules`或整个`.idea`。
2. 安装JDK21、Maven、MySQL8、Redis、Node.js（按现有依赖锁文件使用兼容版本）。IDEA项目SDK及Maven运行JDK统一21，启用Lombok注解处理并重新导入Maven。
3. 建立自己的本地数据库和Redis；新库按初始化说明执行，已有库只跑增量迁移。不要连接原开发者的数据库写入。
4. 自己创建`xunye/src/main/resources/application-local.yml`配置本机连接；它已被忽略，不会自动从GitHub获得。JWT_SECRET等凭据私下配置，文档只提供占位符。
5. 后端默认8890；App H5默认1026；管理端建议5173。端口占用先检查进程，勿随意结束其他人的服务；管理端地址加入CORS白名单。
6. MQ联调时启动NameServer和Broker，按ops说明启用定时消息。可以设置`XUNYE_MQ_ENABLED=false`单独开发创作页面，但此状态不能验收MQ通知和订单自动关单。
7. `xunye`下执行`mvn test`、`mvn -DskipTests package`；App按锁文件安装依赖，再`npm run dev:h5`/`npm run build:h5`。管理端交付相应脚本及锁文件。
8. 初始化普通读者、两位作者、三种角色管理员、普通作品、会员专属作品等独立演示数据，口令不写进公开文档。

## 10. 两人GitHub协作方式

- 原开发者先将可交接的M4代码、增量SQL和本文提交并推送；接手者确认远端内容齐全再开工。未提交/被gitignore的本机内容不会出现在朋友电脑。
- 从最新main分别创建`feature/m5-author-audit`和后续`feature/m6-admin`分支；不要两人长时间直接向main堆积不同功能。
- M5建议拆PR：管理员认证基础 → 作者作品/章节与状态迁移 → 审核工作台 → 收益与联调。M6按模块拆PR。
- 每次PR说明问题、数据库升级方式、接口影响、页面入口和验证结果；由另一人review后合并，不强推main。
- M5合并后再从更新的main创建M6，避免两个分支各自重复写管理员登录和审核。
- 本人继续调整M1～M4时，尽量与朋友约定文件归属；`WebConfig`、`JwtUtils`、`WalletServiceImpl`、公共常量、SQL、`pages.json`属于容易冲突的共享文件，改前沟通并及时合并。
- 迁移脚本与代码在同一PR提交，禁止互相发送整库覆盖对方数据；本地配置、密钥、数据库备份、日志、构建产物不提交。
- 发现冲突逐处确认保留双方业务，不直接整文件选择ours/theirs；合并后重跑相关检查。

## 11. 验收清单

### M5必须通过

- [ ] 普通用户可入驻；未登录/封禁/非作者不能调用创作写接口。
- [ ] 作者A可创建、编辑、预览自己的作品/章节，作者B无法通过改ID读取草稿或修改A的内容。
- [ ] 草稿不进待审列表；送审后进入，撤回/编辑后按规则退出；公共接口不能读取草稿/待审/驳回正文。
- [ ] 作品通过后章节可送审；管理员通过后App能读，驳回展示原因，作者修改重提后能恢复。
- [ ] 并发审核、审核与撤回、旧版本审核冲突有测试；字数和发布计数不重复累计。
- [ ] 同书章节序号并发创建只有一条成功，参数和价格错误有明确提示。
- [ ] 作者可预览自己的会员专属草稿；非VIP通过公共接口仍不能读专属作品。
- [ ] 普通免费/付费章、VIP畅读、会员到期后已购章阅读均保持原行为。
- [ ] 已购章重新编辑不删除购买记录；上线内容修改前有重新审核提示。
- [ ] 收益只包含本人真实收入，列表和汇总可核对。

### M6必须通过

- [ ] App token与管理员token不能互换；三种角色直接请求越权接口都被拒绝，封禁即时生效。
- [ ] 管理模块逐项可用，不止静态页面；筛选/分页/错误/加载状态正确。
- [ ] 历史购章作品不能直接切会员专属，专属切普通的售卖配置完整。
- [ ] 人工增减余额有权限、原因、方向、流水和日志；重复请求不重复调账，失败一起回滚。
- [ ] 套餐改价、改名、下架不影响旧订单快照与旧订阅有效期。
- [ ] 审核记录与业务一致；删除/隐藏内容后的公开可见性与计数一致。
- [ ] 仪表盘样例数据可人工核对，日期补0、时区、已付状态及双边流水去重正确。
- [ ] 新库安装和M4已有库升级各验证一次，不丢历史账户、购买、资金与VIP数据。
- [ ] 既有自动测试保持通过；补充作者归属、状态机、角色、并发、余额幂等和统计口径测试。
- [ ] 后端测试/打包、App与管理端生产构建通过；完成作者→审核→读者端完整手工联调。

不要只写与实现一模一样的断言：测试重点是越权、状态冲突、并发、回滚、历史兼容等真实风险。

## 12. 每阶段交付物与演示顺序

每阶段交付：后端代码、对应前端、增量迁移SQL、可选演示数据、example配置、接口说明、启动说明、验证结果、已知限制。

推荐演示：读者入驻作者 → 新建作品并送审 → 管理员审核 → 作者写章送审 → 驳回并修改 → 再通过 → 普通读者免费/购买阅读 → VIP直接阅读 → 作者查看收益 → 管理端核对交易与统计。

本阶段不包含真实支付、提现、签约、广告系统、AI创作、全文搜索集群或微服务拆分。不要为了完成后台改造现有M1～M4核心交易链路。
