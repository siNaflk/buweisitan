# M4：VIP体系、RocketMQ与业务常量整理

> 2026-11-26阅读规则更新：会员专属作品的所有章节只允许有效VIP阅读，不支持单章购买；普通作品VIP全章畅读，非会员按免费/已购权限阅读。下文以此规则为准。

## 功能入口

- 我的 → VIP会员：查看套餐、余额开通/续费、VIP到期时间、畅读权益、历史订阅。
- VIP会员 → 会员专属：只列出已审核、未下架的会员专属作品；游客可以浏览列表，正文逐次校验权益。
- 我的 → 我的消息：VIP订阅成功、即将到期通知，未读数和标记已读。
- 阅读器：会员专属的所有章节必须有VIP；普通作品VIP全章畅读、非会员免费章直接读、付费章购买后读。专属锁定页只提供开通/续费VIP入口。
- 充值订单：创建后发出定时消息，超过15分钟且仍待支付时自动关闭，不依赖用户再次查询。

M4核心范围是订阅、续费、会员专属和普通作品VIP畅读。广告系统、会员专属阅读主题属于后续可选项。
阅读事件没有接MQ：继续使用BookVisitServiceImpl的Redis聚合和定时刷库。

## 订阅与资金规则

所有金额均为Long整分。套餐价格、有效天数从数据库上架配置读取，不写死在常量类。历史折扣仅保留在兼容字段中。
请求携带requestId和expectedPrice：前者标识同一次提交，后者核对用户确认的价格，不能决定实际扣款额。
同一requestId重试返回原订阅；使用相同标识修改套餐/价格时返回409。前端网络异常会保留提交标识，避免重试双扣。

首次或已过期：开始时间取当前时间；未过期续费：从当前到期时间顺延，保留剩余天数。
所有VIP套餐享有相同的畅读权益，仅有效天数与价格不同。历史折扣字段保留兼容，不再用于新阅读权限或扣款。
名称、天数及历史折扣字段保存在vip_subscription_detail快照中，订阅和资金记录不会被改写。
历史手工设置到期时间但无订阅快照的VIP，也按统一VIP到期时间判定，享有普通作品全章畅读和会员专属阅读权益。

会员有效期判定统一在VipService.isVip。章节内容接口和WalletService购买接口均按有效VIP判断是否免购章。
VIP畅读时不生成购买记录、购章扣款或作者分成流水；VIP到期后，仅普通作品中实际购买过的章节保持买断权限。会员专属不因isFree标记、作者身份或历史单章购买记录而向非会员放行。
余额更新、type=7的VIP支出流水、订阅记录、权益快照、到期时间、本地消息在同一数据库事务中提交或回滚。
充值、购章、打赏、VIP扣款均沿用原有数据库行锁/唯一约束与Redis防连点，不将资金流水异步化。

## MQ设计

使用官方rocketmq-client 5.3.0直接集成，后端仍是Spring Boot 3，不引入旧版Boot2自动配置starter。

| 场景 | Topic | 消费动作 |
| --- | --- | --- |
| ORDER_TIMEOUT | xunye-order-timeout-topic | 锁定订单，确认仍待支付且确实到期，再关闭 |
| VIP_OPENED | xunye-vip-notify-topic | 生成本人站内订阅通知 |
| VIP_EXPIRING | xunye-vip-notify-topic | 到期前3天内提醒，已续费的旧提醒丢弃 |

超时消息使用5.x定时投递时间setDeliverTimeMs，broker必须开启timerWheelEnable。
不要把15分钟误写成旧版延迟等级16：官方旧版默认等级16是30分钟。

生产可靠性：业务事务写mq_outbox，后台每轮间隔2秒发布。MQ断线时保留消息、指数退避重试，最长间隔5分钟，不影响已经成功的VIP权益。
消费者以服务端本地消息ID查数据库，不信任MQ中传来的用户/金额等业务字段。
消费时锁定消息行，通知或关单与consumed_at同一事务提交；异常整体回滚，MQ返回重试。
同一事件重复或并发投递，只会产生一次通知；长时间已发送未消费的记录会被重新投递作为补偿。
M3已有待支付订单会由后台补齐超时消息，分批扫描只找缺少事件的记录，避免批次饥饿。
到期提醒每小时扫描，event_key含用户ID和到期时间，同一有效期只生成一次提醒。
Broker使用独立本地存储目录和SYNC_FLUSH，不修改原有rocketmq/conf/broker-dev.conf。
这些机制提高可靠性，仍需要在部署环境维护MySQL和Broker存储/监控，不宣称任意硬件故障下绝对不丢消息。

## 数据库与配置

本机已执行sql/m4-migration.sql，仅CREATE TABLE IF NOT EXISTS，不覆盖旧套餐和旧订阅。
新增vip_subscription_detail、mq_outbox、user_notification；并兼容缺少基础VIP表的M3库。
sql/m4-demo-data.sql仅当完全没有上架套餐时提供月/季/年演示套餐；已有配置保留。
迁移到其他已有M3数据库时执行上述增量脚本，不要重跑含DROP TABLE的新建库脚本xunye.sql。

新增配置：

```yaml
xunye:
  mq:
    enabled: true
    nameserver: 127.0.0.1:9876
```

可通过XUNYE_MQ_ENABLED和ROCKETMQ_NAMESERVER环境变量调整。
关闭MQ时资金事务仍可成功，本地事件保留，通知和后台关单等待MQ重新启用；支付接口仍拒绝过期订单。

## 本机启动

当前安装目录为C:\develop\rocketmq\rocketmq-all-5.3.0-bin-release。

1. 在后端目录运行 `.\ops\start-rocketmq.ps1`，启动本项目NameServer（9876）和Broker（10911）。脚本可传RocketMqHome、JavaHome调整本机路径。
2. IDEA重载Maven后重启XunYeApplication（8890）。项目编译使用JDK21；本机MQ脚本使用已安装JDK8。
3. 刷新前端，进入我的 → VIP会员。前端依赖没有新增。
4. `.\ops\stop-rocketmq.ps1`只停止记录且命令行仍匹配的本项目中间件进程。

本机Broker配置位于ops/rocketmq-broker.conf，数据、进程ID和日志位于仓库根.runtime/rocketmq，已被.gitignore排除。
默认安装路径与存储路径属于本机演示配置，换电脑需修改ops配置中的路径。
不要启动旧broker-dev.conf后仍期望支持M4定时消息，它没有启用timerWheelEnable。

同时显式配置了Maven Lombok annotationProcessorPaths，并启用本地IDEA注解处理，解决搬目录后getMsg/getCode等生成方法找不到的问题。

## 常量整理

- WalletConstant：订单状态、流水类型、关联类型、锁时长、订单有效期、打赏上限。
- VipConstant：无折扣比例、提前提醒天数、套餐天数上限。
- MqConstant：事件、Topic、消费组、状态、批次数量、重试边界。
- CommonConstant：公共状态、分页上限、百分比基数、错误码与最小付费价格。
- AuthConstant：验证码有效期、登录/注册/发布限流额度。
- RedisKeyConstant：保留原键名，集中钱包锁、浏览计数、限流和登出黑名单前缀。

保留用户原有WalletServiceImpl等改动，仅在相关方法中接入VIP/消息并替换业务数字；不把运营价格误做成Java常量。
Controller、Service接口/impl、MQ传输和本地消息任务均保留中文说明。

## 规则调整的兼容说明

不修改数据库中的章节免费标记、历史订阅、历史折扣快照或购章/资金记录。当前套餐响应的privileges返回统一的畅读权益，前端不再展示九折等历史文案。
ChapterContentRespDto增加vipRequired和canPurchase，明确区分开通会员与单章购买；目录DTO增加vipLibrary，专属作品不再错误显示免费标签。
未来管理端将普通作品改为会员专属时，需要限制存在已售章节的作品切换，或先设计退款方案；目前没有作品类型切换接口，本次不批量变更任何作品归属。

本次新增回归覆盖：会员专属的免费章和历史已购章仍要求VIP；普通作品VIP免购章且不新增资金流水；VIP到期后恢复普通购章规则；普通作品非会员免费章和已购章正常阅读。
