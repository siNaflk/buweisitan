# M3：钱包、购章、打赏与互动点赞

## 已实现

- 我的页面 → 充值与钱包：余额、上架档位、充值订单、确认模拟支付、收支明细。
- 阅读器：付费章节展示服务端价格，确认余额购章后重新加载正文；余额不足引导充值。
- 作品详情 → 支持作者：固定/自定义打赏金额（0.01～1000元）、附言、确认与结果提示。
- 社区列表和帖子详情：点赞数、已赞、取消点赞；回复也支持点赞。
- 书评与章评：保留已有点赞接口，强化按钮展示并回归验证。
- 浏览次数先在Redis聚合，每分钟写回MySQL；Redis故障时回退数据库计数。
- 保持Controller → Service接口 → impl实现 → Mapper分层，新增接口/实现均有关键中文注释。

## 演示规则

金额全程使用Long整分；客户端不能指定充值入账额或作者收入。
充值：服务端读取档位，创建金额/赠送额快照，订单15分钟有效，支付时再核对订单归属和状态。
状态0待支付、1已入账、2已关闭；查询或尝试支付时关闭已过期订单。自动后台关单留待M4消息队列阶段。
模拟支付入口是演示支付确认，不是第三方支付回调，也没有真实资金扣费。

购章：默认按章节price，缺省时使用作品chapterPrice。客户端传expectedPrice只用于核对用户确认的报价；变化时返回409要求重新确认。
同一用户同一章节只保留一条购买记录，重复调用返回已有交易，不重复扣款。
免费章节、作者自己的作品、已有会员书库阅读权益不会再次扣款。
当前M3不实现VIP订阅或购章折扣，属于M4范围。

作者购章分成暂定50%，向下取整到分，可通过 `xunye.payment.author-share-percent` 调整；购买记录保存实际分成快照。
打赏100%进入作者余额；禁止给自己的作品打赏。所有收支都记balance_flow。
同一打赏的网络重试复用requestId；同一ID携带不同作品/金额/附言时拒绝。
同一充值提交复用requestId；重复支付同一订单不会重复入账。
前端保留未确认订单/打赏提交标识，避免网络错误后直接生成另一笔交易。

## 一致性与权限

- 交易接口全部强制登录，操作用户由UserContext取得，不能由前端指定。
- Redis SET NX + 15秒短锁防连点；随机锁值与Lua比较删除，避免删掉其他请求的锁。
- 数据库账户行锁、购买/充值/打赏唯一约束兜底，Redis锁不是唯一保障。
- 多账户按用户ID升序加锁，降低相互打赏时的死锁风险。
- 资金事务使用READ_COMMITTED，等待账户锁后可以看到刚提交的幂等记录，避免MySQL默认可重复读的旧快照问题。
- 余额更新、双方流水、购买/打赏/支付状态同事务提交；任一步异常整体回滚。
- 不缓存余额，不通过异步MQ补写资金流水。
- 仅公开且未封帖的帖子/已审核回复可点赞，待审、驳回、删除内容不能绕过审核获得点赞。
- 论坛点赞关系唯一约束(user_id,target_type,target_id)，1帖子/2回复；计数直接统计关系表，重复点赞/取消不会漂移。
- 书评/章评继续使用comment_like与事务内计数；游客可看点赞数，操作需登录。

## 接口

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | /api/app/wallet | 本人余额与模拟支付开关 |
| GET | /api/app/wallet/plans | 上架充值档位 |
| GET | /api/app/wallet/flows?pageNum=1&pageSize=20 | 本人收支分页 |
| POST | /api/app/wallet/recharge | 创建订单：planId、requestId |
| GET | /api/app/wallet/recharge/{id} | 本人订单状态 |
| POST | /api/app/wallet/recharge/{id}/simulate-payment | 确认模拟支付 |
| POST | /api/app/chapter/buy/{id} | 确认购章：expectedPrice，单位分 |
| POST | /api/app/book/tip/{id} | 打赏：amount、message、requestId |
| POST / DELETE | /api/app/interaction/forum/posts/{id}/like | 点赞/取消帖子点赞 |
| POST / DELETE | /api/app/interaction/forum/replies/{id}/like | 点赞/取消回复点赞 |
| POST / DELETE | /api/app/interaction/comments/{id}/like | 书评/章评点赞，沿用M2 |

模拟支付默认开启，部署到真实环境前可设置环境变量 `SIMULATED_PAYMENT_ENABLED=false` 禁用。
浏览计数可用 `xunye.stats.redis-enabled=false` 切换为同步数据库计数；汇总间隔 `xunye.stats.flush-ms` 默认60000。
浏览计数允许短暂延迟；进程在取走Redis计数后突然崩溃可能丢失该批浏览统计，不能将该机制用于资金。

## 建议体验顺序

1. 重启后端，登录App，进入我的 → 充值与钱包。
2. 选择档位，创建订单，确认模拟支付，查看余额与收支明细。
3. 进入付费章节，确认购章，查看正文解锁；重复打开不会再次扣款。
4. 到其他作者的作品详情打赏，分别查看读者支出和作者收入。
5. 在已审核帖子上点赞，再到回复、书评和章评中点赞/取消，刷新确认状态保留。

## 顺手修复

现有验证码verify/限流代码缺少Redis返回值为空时的判断；恢复空值保护，避免验证码过期时抛空指针。
阅读器重新进入时刷新阅读权限；锁定章节不再保存已读进度，并用请求版本号避免快速切章时旧正文覆盖新章节。
