# 寻页 M2 交付说明

## 已实现

- 手机号/密码注册登录、BCrypt密码、图形验证码、个人信息、退出登录。
- 验证码Redis保存5分钟，Lua原子读取并删除，错误答案也会消费；登录/注册/发内容有限流。
- 每次登录签发独立JWT；同时支持裸token及Bearer；退出后按剩余有效期加入黑名单（只保存token摘要）。
- 管理员token不能进入App用户域；封禁、删除账号立即失去写接口权限；请求结束清理ThreadLocal。
- 书籍详情书评、阅读器章评，分页、发表、删除本人评论、点赞/取消点赞。
- 新增comment_like唯一关系表，事务和评论行锁使重复点赞不重复计数，验证章节所属书籍。
- 社区Tab、公开帖子列表、帖子详情、发帖、回复、我的帖子和审核状态；本人删除帖子/回复。
- 待审/驳回帖子仅本人可查看；公开回复仅展示已通过内容和查看者自己的回复；未审核/封帖不能新增回复。
- 登录返回后刷新详情与书架，修复数字/字符串错误码混用及非响应式登录状态。

## 启动

1. 已有M1数据库只执行 `sql/m2-migration.sql`，该脚本幂等新增点赞表，不删除原数据。不要重新执行会DROP表的 `sql/xunye.sql`。
2. 本次验证已通过临时后端启动执行上述增量脚本（新增comment_like）。可选的 `sql/m2-demo-data.sql` 未自动导入。
3. IDEA后端Project SDK/Maven运行JDK使用21；当前终端默认JDK17，请勿据此修改项目目标版本。
4. MySQL/Redis沿用你现有的 `application-local.yml`。不要把它或真实密钥提交仓库。
5. 停止IDEA中原来的8890后端，再启动XunYeApplication，使M2代码生效。本次临时验证后端使用8891，避免干扰你的8890进程。
6. App目录安装依赖后执行 `npm run dev:h5`，访问 `http://localhost:1026`。已将端口/代理集中到vite.config.js；默认 `/api` 代理8890。
7. 真机运行时，按 `src/utils/config.js` 修改后端局域网IP；手机和电脑需网络互通。

## 手工验收顺序

1. 我的 → 登录/注册 → 点击图形验证码刷新，注册一个新账号（密码8～64位，UTF-8最多72字节）。
2. 收藏一本书，切换书架确认可见；退出登录后确认不再显示上一账号书架。
3. 书籍详情发表书评，点赞/取消点赞；在阅读器发表章评，确认与书评分开。
4. 社区发布找书帖，跳转“我的帖子”看到待审核；退出后公开社区不能看到该待审帖。
5. M6管理端尚未实现。可选导入明确标注的已审核演示帖，或按m2-demo-data.sql末尾说明审核指定ID。
6. 已审核帖可以回复；自己的待审回复仅本人可见；审核后其他用户可见。
7. 换账号验证不能删除他人的评论、帖子、回复；退出后原token不能访问登录接口。

## API（返回沿用 {code,msg,data}）

|方法|路径|说明|
|---|---|---|
|GET|/api/app/user/captcha|验证码 {captchaId,image}，image是PNG data URL|
|POST|/api/app/user/register|phone/password/captchaId/captcha/nickname，返回token和user|
|POST|/api/app/user/login|phone/password/captchaId/captcha|
|GET|/api/app/user/me|本人脱敏信息，无密码|
|POST|/api/app/user/logout|服务端令牌失效|
|GET|/api/app/comments|bookId、可选chapterId、pageNum/pageSize；不传chapterId为书评|
|POST|/api/app/interaction/comments|bookId、可选chapterId、content|
|DELETE|/api/app/interaction/comments/{id}|删除本人评论|
|POST/DELETE|/api/app/interaction/comments/{id}/like|点赞/取消点赞|
|GET|/api/app/forum/posts|公开帖子分页|
|GET|/api/app/forum/posts/{id}|公开或本人帖子|
|GET|/api/app/interaction/forum/mine|本人帖子（含审核状态）|
|POST|/api/app/interaction/forum/posts|title/content，默认待审核|
|DELETE|/api/app/interaction/forum/posts/{id}|删除本人帖子|
|GET|/api/app/forum/posts/{id}/replies|公开回复及本人待审回复|
|POST|/api/app/interaction/forum/posts/{id}/replies|content，默认待审核|
|DELETE|/api/app/interaction/forum/replies/{id}|删除本人回复|

所有interaction接口和除captcha/register/login外的user接口均需登录。分页每页最多50条。5005清除前端登录态。业务错误仍沿用M1响应code协议。

## 验证与限制

- 后端 `mvn test`：H2隔离数据库集成测试覆盖真实Controller/Service/Mapper；Redis用Mock隔离。
- CaptchaService测试覆盖PNG生成、5分钟保存、验证码重复/错误拒绝；真实Redis的Lua另外通过本地接口验证。
- 前端H5生产构建通过；未验证Android真机安装包或微信小程序完整交互。
- 管理端审核及驳回理由属于M6，不为演示把帖子默认自动通过；M2展示审核状态。
- M1阅读进度仍为本地保存，阅读偏好云同步、支付、VIP及创作未在M2扩展。
- 注册手机号当前只是登录标识，没有短信验证；发布前若需确认号码归属，应补短信验证或学校身份认证。

## 后续设计建议

1. M3资金流水应与余额和购买记录处于同一个数据库事务，不能按旧文档用普通异步消息单独写流水。
2. MQ消费去重不能只在处理前SET Redis标志，否则中途失败可能吞消息；用数据库幂等约束与事务完成后记录消费结果。
3. M6审核内容时同步维护公开计数并留审核记录；当前论坛公开回复数按已通过记录实时查询，避免展示待审内容数量。
4. 本次未提交Git或推送远端，两个仓库的改动保留在工作区供你审阅。
